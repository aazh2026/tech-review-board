# 技术评审与决策管理平台 (Tech Review Board Platform)

> **治理模式**：企业级多产品族技术治理与分级决策平台（**模式 C：分级授权管理**）  
> **核心宗旨**：落实三级 DRB 治理、智能议题路由、申报材料 SHA-256 快照冻结、委员独立表决、授权裁决签发、P0/P1 整改独立验证与 ADR 知识库闭环。

---

## 🌟 核心理念与三权分立原则

平台严格贯彻架构治理的核心准则——**“三权分立”与“分级闭环”**：
1. **评审权（专业质询）**：专项专家与架构师独立提出技术异议与分级缺陷（P0-P3），不受行政干扰。
2. **表决权（民主票决）**：各级 DRB 委员依据事实独立投出表决票（赞成/附条件/反对/弃权），实到人数与赞同率必须达到双 2/3 法定多数。
3. **决策权（授权裁决）**：DRB 主席依照分级授权章程签署正式决策书，并对企业级技术基线终局负责。
4. **验证权（独立核验）**：整改责任人不得作为自身整改项的唯一核验人；未完成 P0/P1 阻断项核验的议题严禁归档。

---

## 🔄 核心治理主流程

平台聚焦端到端评审流转，实现无断点的全链路数据闭环：

```mermaid
flowchart LR
    A[个人待办/工作台] --> B[议题向导式申报]
    B --> C[秘书准入受理与路由]
    C --> D[材料快照SHA-256冻结]
    D --> E[AI合规初审与预警]
    E --> F[评审会中质询与转问题]
    F --> G[委员独立表决与门槛计算]
    G --> H[主席签署正式决议书]
    H --> I[P0/P1整改方案提交与独立核验]
    I --> J[闭环门禁诊断]
    J --> K[正式归档关闭 & ADR沉淀]
```

## 🧭 系统六大功能模块

| 模块名称 | 路由标识 | 功能概述 |
| :--- | :--- | :--- |
| **评审工作台** | `workbench` | 个人待办任务聚合（待初审/待表决/待整改/待核验/待决策）、全流程统计大盘、快捷新建与流转。 |
| **议题管理与申报** | `topics` | 议题全生命周期主战场：向导式填报、智能级别路由（L1/L2/L3）、材料快照冻结、AI 合规初审、跨级升级与闭环雷达。 |
| **评审会议与表决** | `meeting` | 会议工作台：审议议题切换、三模式控制台（会前签到、会中议程与质询登记、委员独立表决、会后决策衔接）。 |
| **意见与整改闭环** | `comments` | P0-P3 缺陷清单、责任人提交整改方案与代码 PR 证据、独立专家核验通过/驳回、残余风险接受审批。 |
| **正式决策与ADR** | `decisions` | 授权裁决书签署、版本化修订发布（BR-027）、架构决策记录（ADR）自动同步入库与全文检索。 |
| **DRB组织与授权** | `drb` | 三级 DRB 纵向层级（L1 企业级/L2 产品族/L3 产品级）、横向专项专家组、分级授权矩阵与章程基线。 |

## 👥 演示角色与权能对照

系统顶栏右上角支持**随时一键切换代入角色**，以体验不同治理主体的权责视图：

- 👑 **张建国**（L1 企业级 DRB 主席 / 技术委员会主任）：拥有全集团重大架构裁决签发权、例外审批权与终局闭环关闭权。
- 📋 **赵晴**（L2 营销服务 DRB 秘书）：负责议题准入形式审查、排期受理、材料快照版本冻结。
- 🛡️ **陆天恒**（集团首席安全官 / 安全委员会主任）：负责安全与数据合规红线初审、会中 P0 阻断项提出、整改独立核验。
- 💻 **李晨**（资深架构师 / 议题申报人）：负责新建议题填报、提供架构设计方案、提交 P0/P1 代码整改证据与 PR 链接。
- 🗳️ **委员会各委员**：独立行使评审会议表决权。

## 🛠️ 技术栈与工程规范

- **前端框架**：React 19 + TypeScript
- **构建工具**：Vite 8
- **样式系统**：Tailwind CSS
- **状态管理**：React Context (`GovernanceContext`)
- **图标体系**：Lucide React
- **端口配置**：3000 (`0.0.0.0`)
- **代码规范**：严格类型检查 (`tsc --noEmit`)
